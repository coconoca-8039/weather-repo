# Weather Discord

NOAAの数値予報モデル GFS のデータを取得し、
日本周辺の気象図をPythonで生成してDiscordへ送信する個人用システム。

現在はMacBook上で実行。
将来的にはRaspberry Piでの定期自動実行を想定している。

---

## システム概要

処理の流れは以下。

1. Herbieを使用してGFSデータを取得
2. xarrayで必要な気象要素を抽出
3. Matplotlib / Cartopyで日本周辺を描画
4. PNGとして `images/` に保存
5. Discord Webhookを使用して5枚まとめて送信

GFSの完成済み天気図画像を取得しているのではなく、
GFSの数値データからPythonで独自に気象図を生成している。

---

## データ

使用モデル：

GFS (Global Forecast System)

米国NOAA/NCEPが運用する全球数値予報モデル。

Herbieでは以下を指定。

```python
model="gfs"
product="pgrb2.0p25"
```

`pgrb2.0p25` は0.25度格子のGRIB2データ。

実行時にはHerbieが利用可能な最新GFSサイクルを検索する。

ログ例：

```text
model=gfs
product=pgrb2.0p25
2026-Aug-22 06:00 UTC F00
GRIB2 @ aws
```

今回の取得では、NOAAがAWS Open Dataとして公開している
GFSデータが使用されている。

# 作成する気象図

対象範囲は概ね

- 経度：100°E ～ 160°E
- 緯度：15°N ～ 60°N

として、日本とその周辺を表示する。

各図は最新のGFS初期値（F00）を使用する。図の時刻はUTC表記なので、
日本標準時（JST）で見る場合は9時間を加える。

以下の「見る観点」は、個々の要素だけで天気を断定するためのものではない。
地上から上層までを重ね合わせ、湿り・上昇流・風・気圧配置が整合しているかを
確認するための目安として使用する。

## Surface

ファイル：

```text
scripts/ASurface.py
images/surface.png
```

表示内容：

- 海面更正気圧
- 高気圧・低気圧の中心（H・L）
- 10 m風

海面更正気圧を等圧線として表示する。
等圧線間隔は4 hPa。

等圧線は赤、Hは青、Lは赤で表示し、10 m風を矢羽根で重ねる。
H・Lは格子点の局所的な極大・極小から機械的に抽出した目安であり、
気象機関による解析位置と必ずしも一致しない。

タイトル：

```text
GFS Surface Pressure
```

見る観点：

- 等圧線の形から、高気圧・低気圧、気圧の谷、尾根の位置をつかむ。
- 等圧線の間隔が狭い場所ほど気圧傾度が大きく、風が強まりやすい。
- 地上風が等圧線を横切って低圧側へ向かう様子や、地形・摩擦の影響を見る。
- 低気圧中心だけでなく、そこから延びる気圧の谷と風向変化にも注目する。
- 降水域はこの図には描かれていないため、700 hPa湿度・上昇流や雲量図と組み合わせる。

## 850 hPa

ファイル：

```text
scripts/A850hPa.py
images/850hPa.png
```

表示内容：

- 850 hPa 気温
- 850 hPa ジオポテンシャル高度
- 850 hPa 風

気温を背景色として表示。

カラーマップは `viridis` を使用し、
他の高層図と色調をある程度統一している。

ジオポテンシャル高度は黄色の等高度線。

風は黒の矢羽根で表示。
GFSの0.25度格子をそのまま描くと密集するため、
格子を間引いて表示している。

タイトル：

```text
GFS 850 hPa Temperature + Geopotential Height + Wind
```

主な用途：

暖気・寒気の分布と、その移流を風と合わせて確認する。

見る観点：

- 気温分布と風向を重ね、暖気移流・寒気移流の向きと強さを見る。
- 等温線を横切る風が強い場所ほど、気温移流が明瞭になりやすい。
- 気温の水平傾度が大きい帯は、前線帯や気団境界を考える手掛かりになる。
- 850 hPaは下層気団の把握に便利だが、標高の高い地域では地面より下になる場合がある。
- 地上図の低気圧・風と対応させ、低気圧前面の暖気流入や後面の寒気流入を確認する。

## 700 hPa

ファイル：

```text
scripts/A700hPa.py
images/700hPa.png
```

表示内容：

- 700 hPa ジオポテンシャル高度
- 700 hPa 相対湿度
- 700 hPa 鉛直流

相対湿度を背景色として表示。

ジオポテンシャル高度をシアンの等高度線として表示。

鉛直流は黒の等値線として表示。
負の鉛直流を上昇流として見る。

タイトル：

```text
GFS 700 hPa Height + Relative Humidity + Vertical Velocity
```

主な用途：

中層の湿潤域と上昇流の位置関係を見る。

特に、

「湿っている領域」と「上昇流」

が重なっている場所を確認する。

※ 情報量が多く、現在の5枚の中では比較的複雑な図。

見る観点：

- 相対湿度が高いだけでなく、負の鉛直p速度（上昇流）が重なる場所を優先して見る。
- 湿潤域だけなら雲はあっても、必ずしも活発な降水を意味しない。
- 上昇流だけでも、中層が乾燥していれば雲・降水が発達しにくい場合がある。
- 湿潤域と上昇流が広く重なる場所は、まとまった雲域や降水域の候補になる。
- 850 hPaの暖湿気流入、500 hPaのトラフ・渦度との位置関係も確認する。

鉛直流は通常の上下方向の速度ではなく鉛直p速度（Pa/s）で、
この図では負の値ほど上昇流が強い。対流性の激しい上昇流はモデルの格子や
時間間隔で平滑化されるため、値を局地的な突風・雷雨の強度へ直接読み替えない。

## 500 hPa

ファイル：

```text
scripts/A500hPa.py
images/500hPa.png
```

表示内容：

- 500 hPa ジオポテンシャル高度
- 500 hPa 絶対渦度

絶対渦度を背景色として表示。

ジオポテンシャル高度を等高度線として重ねる。

タイトル：

```text
GFS 500 hPa Geopotential Height + Absolute Vorticity
```

主な用途：

- トラフ
- リッジ
- 寒冷渦
- 上空の大規模な流れ

などの把握。

見る観点：

- 高度線が南へ張り出す部分をトラフ、北へ張り出す部分をリッジとして追う。
- 閉じた低高度域や等高度線の強い曲率は、寒冷渦・切離低気圧の手掛かりになる。
- 正の絶対渦度が大きい領域そのものだけでなく、その移動方向と下流側に注目する。
- トラフ前面で700 hPaの上昇流・湿潤域が重なるかを見る。
- 地上低気圧に対して上空のトラフが西側にある配置は、発達を考える材料の一つになる。

絶対渦度の着色値は `1e5` を乗じて表示している。
渦度が大きいことだけで地上低気圧の発達や悪天を断定せず、
高度場、温度移流、湿潤域との組み合わせで判断する。

## 300 hPa

ファイル：

```text
scripts/A300hPa.py
images/300hPa.png
```

表示内容：

- 300 hPa ジオポテンシャル高度
- 300 hPa 風速
- 300 hPa 風

U成分とV成分から風速を計算。

```python
wind_speed = np.sqrt(u ** 2 + v ** 2)
```

風速を背景色として表示。

ジオポテンシャル高度は黄色の等高度線。

風向・風速は黒の矢羽根として表示。

タイトル：

```text
GFS 300 hPa Geopotential Height + Wind Speed + Wind
```

主な用途：

上層の偏西風およびジェット気流の位置・蛇行を確認する。

見る観点：

- 風速の大きい帯をジェット気流として追い、軸の位置や蛇行を見る。
- ジェットの入口・出口、風速の増減、流れの曲がりに注目する。
- 500 hPaのトラフ・リッジが上層の強風帯とどう対応しているか確認する。
- 日本付近だけでは流れの上流側を捉えにくいため、北太平洋版と併用する。
- 上層発散・収束はこの図に直接描いていないため、風速分布だけから機械的に断定しない。

## 北太平洋300 hPa

ファイル：

```text
scripts/300hPa_pacific.py
images/300hPa_pacific.png
```

経度100°E～260°E、北緯25°～80°を対象に、300 hPaの風速、
ジオポテンシャル高度、風を表示する。日付変更線をまたぐ北太平洋全体を見ることで、
日本付近へ近づくトラフやリッジ、ジェット気流の蛇行を上流側から追跡できる。

見る観点：

- 日本周辺図だけでなく、アジア東岸から北米までの波列を一続きで見る。
- 上流側のトラフ・リッジが東進した場合、日本付近の流れがどう変化しそうかを考える。
- 強風軸が南北に蛇行している場所、分流・合流している場所を確認する。
- この図もF00の解析場であり、将来位置を知るには予報時間を進めた図が別途必要になる。

## 全雲量

ファイル：

```text
scripts/cloud_cover.py
images/cloud_cover.png
```

大気全層の全雲量を0～100%で表示する。黒に近いほど雲が少なく、
白に近いほど雲が多い。全雲量は雲に覆われる面積割合であり、雲底・雲頂高度や
雲の厚さ、降水の有無は直接示さない。

見る観点：

- 地上の気圧の谷、700 hPaの湿潤域・上昇流と雲域が対応しているかを見る。
- 雲量が多くても薄い上層雲だけの場合があり、必ずしも雨や雪を意味しない。
- 雲量が少ない領域では放射冷却や日射の効き方が変わるが、地上気温は別要素で確認する。

## 気温・相対湿度・東西風の鉛直断面

ファイル：

```text
scripts/vertical_temp_rh_u.py
images/vertical_125E_temp_rh_u.png ～ vertical_155E_temp_rh_u.png
```

東経125°～155°を5°間隔で切り、北極側から赤道までの鉛直断面を表示する。
背景色は気温（°C）、黒線は相対湿度（%）、白線は東西風（m/s）。
縦軸は気圧で、上ほど高度が高い。

見る観点：

- 対流圏内の寒気・暖気の厚みと、緯度方向の温度傾度を見る。
- 高湿度層が下層だけか、中層・上層まで深く広がっているかを確認する。
- 東西風の極大域からジェットの緯度・高度を捉える。正値は西風、負値は東風を表す。
- 同じ現象を複数経度の断面で比較し、東西方向の広がりや傾きを把握する。
- 気圧面は地形の影響を受けるため、下層では地下に相当するデータが含まれる場合がある。

## 相当温位・風の鉛直断面

ファイル：

```text
scripts/thrtae_wind.py
images/thetae_wind_140E.png
```

東経140°、北緯50°～20°の断面に相当温位（K）と風を表示する。
相当温位は気温と水蒸気量をまとめて捉える指標で、値の高い空気ほど暖かく湿っている。

見る観点：

- 下層の高相当温位域から、暖湿気がどの緯度・高度まで流入しているかを見る。
- 相当温位の水平傾度が大きい帯を、気団境界・前線帯を考える手掛かりにする。
- 相当温位が鉛直方向に減少する層は対流不安定の可能性を示すが、発雷を直接保証しない。
- 風向・風速と合わせ、暖湿気の供給が継続しそうかを確認する。

## 湿数・上昇流の鉛直断面

ファイル：

```text
scripts/dewpoint_upward.py
images/dewpoint_depression_upward_motion_140E.png
```

東経140°、北緯50°～20°の断面を表示する。背景色は上昇流の強さ
（負の鉛直p速度の符号を反転した値）、黒線は湿数（気温－露点温度、°C）。
湿数が小さいほど空気は飽和に近い。

見る観点：

- 湿数3°C前後の領域を、飽和に近い層の目安として見る。
- 湿った層の深さと、上昇流が重なる高度を確認する。
- 下層から中層まで湿潤か、乾燥層が途中に挟まるかを見る。
- 強い上昇流と小さい湿数が重なる場所は雲・降水域の候補になるが、降水量そのものではない。

## Skew-T（土浦）

ファイル：

```text
scripts/skewt.py
images/skewt_tsuchiura.png
```

土浦付近（36.08°N、140.20°E）の気温、露点温度、風を気圧高度ごとに表示する。
黒実線が気温、青実線が露点温度で、乾燥断熱線・湿潤断熱線・混合比線を補助線として描く。

見る観点：

- 気温線と露点線の間隔が狭い層ほど湿っており、雲層の候補になる。
- 逆転層や安定層、上空寒気の有無を気温線の傾きから確認する。
- 風矢羽根の高度変化から鉛直シアを見る。
- この図は離散的な気圧面のGFSデータを結んだもので、実際の高層観測ほど細かな層構造は表現できない。
- 現在の図にはCAPE、CIN、LCLや持ち上げた空気塊の経路を描いていないため、対流発生を単独では判定しない。

## 図を組み合わせて見る順番

1. 地上図で高低気圧、気圧の谷、地上風を確認する。
2. 850 hPaで下層の暖気・寒気と、その移流を確認する。
3. 700 hPaで湿潤域と上昇流が重なる場所を探す。
4. 500 hPaでトラフ、寒冷渦、渦度分布を確認する。
5. 300 hPaでジェット気流と上層の大きな流れを確認する。
6. 雲量図で実際のモデル雲域との対応を見る。
7. 必要に応じて鉛直断面やSkew-Tで、大気の厚み方向の構造を確認する。

複数の高度で同じ場所にシグナルが重なるほど、現象を説明しやすくなる。
一方、一つの図だけが強いシグナルを示す場合は、時刻差、位置ずれ、モデル解像度、
地形の影響も含めて慎重に見る。

# 画像保存

生成画像は以下に保存。

```text
images/
    surface.png
    850hPa.png
    700hPa.png
    500hPa.png
    300hPa.png
```

ファイル名は固定。

実行するたびに前回の画像を上書きする。

過去画像は現在の仕様では保存しない。

Matplotlibでは概ね以下の形式で保存。

```python
plt.savefig(
    "images/500hPa.png",
    dpi=150,
    bbox_inches="tight"
)

plt.close()
```

自動実行時に画像ウィンドウが開いて処理が停止しないよう、
`plt.show()` は使用せず `plt.close()` を使用する。

# Discord送信

Discord Webhookを使用。

Botは使用していない。

Pythonの `requests` からWebhookへHTTP POSTし、
生成した5枚のPNGを一つのDiscordメッセージに添付する。

送信メッセージ：

```text
GFS Weather Charts
```

Webhook URLは外部へ公開しないこと。
Webhook URLを知っている第三者は投稿できるため、
認証情報として扱う。

# 一括実行

`run_all.sh` から各Pythonファイルを順番に実行する。

```bash
#!/bin/bash

cd "$(dirname "$0")" || exit 1

echo "=== Weather charts start ==="

python3 ASurface.py
echo "Surface Fin"

python3 A850hPa.py
echo "850 hPa Fin"

python3 A700hPa.py
echo "700 hPa Fin"

python3 A500hPa.py
echo "500 hPa Fin"

python3 A300hPa.py
echo "300 hPa Fin"

python3 discord_send.py
echo "Discord Send Fin"

echo "=== Weather charts complete ==="
```

macOSでは `python` ではなく `python3` を使用。

実行：

```bash
./run_all.sh
```

初回のみ実行権限を付与する。

```bash
chmod +x run_all.sh
```
